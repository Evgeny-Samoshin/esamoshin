# План реализации сайта SAMOSHIN

> Бриф для реализации в Claude Code. Стек: чистый HTML/CSS/JS, без фреймворков.
> Целевая версия — сразу с механикой погружения.
> Опирается на два документа: konspekt_proekta.md (текст/логика) и design_konspekt.md (визуал/механика). Держать их рядом.

---

## 0. Что за сайт

Персональный сайт-бренд веб-разработчика (SAMOSHIN / «Сайты для бизнеса»). Не визитка — интерактивный сайт-квиз с эффектом погружения. Цель: довести посетителя до заполнения брифа. Сам сайт = демонстрация мастерства (клиент судит о навыке по сайту).

**Позиционирование:** прозрачный процесс, клиент контролирует каждый этап. Тон — на «ты», разговорный. Визуал — утончённый премиум (холодный перламутр, элегантный курсив), контраст простого текста и дорогого вида.

---

## 1. Архитектура состояния (решить ДО вёрстки)

Чистый JS без реактивности — состояние вести явно, иначе каша. Единый объект состояния + рендер-функции по экрану.

```
state = {
  screen: 'start' | 'branch-intro' | 'phases' | 'site-types' | 'brief' | 'brief-done',
  briefEntry: 'start-button' | 'corner-icon' | 'walked' | null,  // как вошли в бриф — определяет возврат
  currentPhase: 0..5,
  briefStep: 0..6,
  briefData: { ... },        // ответы, persist в localStorage
  overlay: null | 'faq' | 'portfolio',
  transition: null | 'dive' | 'blink' | 'flight' | 'dive-back'
}
```

**Ключевое:** `briefEntry` запоминается при входе в бриф — от него зависит анимация возврата (см. раздел 6). Не потерять.

**localStorage:** только `briefData` + timestamp. Очистка после успешной отправки + протухание через неделю. (Прим.: в артефактах Claude localStorage не работает — но это Claude Code, обычный сайт, всё ОК.)

## 2. Дизайн-токены (CSS-переменные)

```css
:root {
  --bg: #F2F3F5;        /* холодный перламутр, НЕ тёплый крем */
  --ink: #1C1E22;       /* графит, основной текст */
  --sky: #7FB2E8;       /* акцент, небесно-воздушный */
  --sky-deep: #4A8FD4;  /* насыщенный акцент — ховеры/интерактив */
  --muted: #6B7078;     /* второстепенный текст */
  --logo: #C8CBD0;      /* логотип, светло-серый (+ градиент вниз к #E4E6E9) */
}
```

**Типографика:** display — serif с элегантным курсивом (заголовки, акцентные слова курсивом, можно в цвет `--sky`). Body — чистый нейтральный sans. Конкретные гарнитуры подобрать на рендере, начать с системных / Google Fonts кандидатов.

**Дисциплина:** одна смелость — интерактив. Типографика тихая опора. Минимум форматирования, много воздуха.

## 3. Структура экранов

```
СТАРТ
 ├─[кнопка «Узнать стоимость сайта»]──── погружение ──→ БРИФ (entry: start-button)
 └─[кнопка «Познакомиться с процессом»]─ погружение ──→ ВЕТКА
                                                          │
   ВЕТКА (последовательность погружения):                │
     1. Экран-обещание                                    │
     2. Шесть фаз процесса                                │
     3. Типы сайтов                                       │
     4. ──── последний рывок камеры ──→ БРИФ (entry: walked)
                                                          │
   Иконки по углам (только внутри ВЕТКИ):                 │
     ┌ верх-лево:  Портфолио (текст) ──── моргание ──→ ПОРТФОЛИО (слой)
     ┌ верх-право: FAQ (иконка ?) ──────────────────→ FAQ (слой поверх)
     ┌ низ-лево:   Позвонить (тел) ─────────────────→ tel: (без анимации)
     └ низ-право:  Узнать стоимость (текст) ─ полёт ─→ БРИФ (entry: corner-icon)
```

**Стартовый экран чистый:** большой логотип SAMOSHIN во всю ширину (светло-серый, вертикальный градиент сверху темнее→снизу светлее), под ним мелко тёмным «Сайты для бизнеса», по центру две кнопки. Больше ничего.

## 4. Механика погружения (signature)

**Два языка перехода:**
- **Погружение** — элемент распадается (дым/растворение), камера рывком уходит вперёд-вглубь, проявляется новый экран. Смысл: движение вперёд по процессу.
- **Моргание** — плавное затемнение → плавное проявление. Смысл: переход в другое место.

**Тайминг:** рывок камеры короткий, уверенный, с быстрым затуханием (dolly-in). Не медленный (убаюкивает), не резкий (бьёт). Обратный ход — быстрее прямого.

**Реализация без 3D:** «камера вперёд» имитируется через scale + opacity + blur на слоях. Уходящий экран: scale up + fade + blur. Приходящий: scale from 0.9 + fade in. CSS transforms + `will-change`, без тяжёлых библиотек.

**Фон — дым (отдельный слой, см. раздел 9).** На старте реализации — заглушка (статичный перламутровый градиент или лёгкая CSS-анимация). Дым навешивается позже, не блокирует сайт.

## 5. Шесть фаз процесса

Свободный скролл с магнитом (scroll-snap или кастомный). Карточка уходит **влево-на-зрителя** (translateX + translateZ-имитация через scale + fade). Обратный скролл возвращает. После последней фазы — рывок на следующий экран.

**Контент фаз** (каждая: заголовок + суть + «Получаешь:»):
1. **Бриф и план** — заполняешь бриф, составляю план с этапами и ценами, созваниваемся. *Получаешь:* план, где видно за что и когда платишь.
2. **Анализ проекта** — конкуренты, клиенты, структура сайта. *Получаешь:* карту сайта и путь клиента.
3. **Дизайн** — референсы, концепции, тексты и изображения, прототип, отрисовка. *Получаешь:* макет, включая мобильную и десктопную версию.
4. **Разработка** — вёрстка, код, адаптив. *Получаешь:* живой сайт на тестовой ссылке.
5. **Запуск** — деплой на хостинг, при необходимости CMS. *Получаешь:* работающий сайт на твоём домене.
6. **Поддержка** *(по желанию)* — техбаги и правки контента. *Получаешь:* уверенность, что сайт под присмотром.

**Подсказки:** ПК — анимированная иконка скролла справа от блока; мобильные — микро-дёрганье первой карточки влево при появлении. Обе гаснут после первого взаимодействия.

## 6. Бриф

**Шапка:** «Ответь на несколько вопросов о проекте — это займёт пару минут. В ответ пришлю план работ с этапами и ценами. Это бесплатно и ни к чему не обязывает.»

**7 шагов, все обязательны, формат — выбор вариантов** (+ «свой вариант» где уместно). Свободный ввод только в шаге 1 и контактах. Сам бриф — скроллящийся список, минимум анимации, обычные ховеры (тихое рабочее место после полёта).

1. **О твоём деле** (ввод):
   - «Чем занимается твой бизнес?» plh: «Например: юрист по банкротству, доставка цветов, студия мебели на заказ»
   - «Кто твои клиенты?» plh: «Например: частные лица, компании, и те и другие»
2. **Что должен делать сайт?** (один): Продать конкретную услугу или продукт / Рассказать о компании и услугах / Показать всё, что мы делаем: услуги, команда, проекты / Продавать товары через интернет / Свой вариант
3. **Что должно быть на сайте?** (несколько): Услуги или товары / Цены, прайс / Отзывы / Фото работ, портфолио / Форма заявки / О компании, команда / FAQ / Блог, новости / Свой вариант
4. **Как сайт должен выглядеть?** (один): Строго и минималистично / Ярко и смело / Дорого и престижно / Современно и технологично / Пока не знаю — доверюсь тебе / Свой вариант
5. **Что уже есть из материалов?** (несколько): Логотип / Тексты / Фотографии / Фирменные цвета, брендбук / Пока ничего нет / Свой вариант
6. **Технические детали:**
   - «Хочешь сам менять тексты и фото после запуска?» → Да, хочу сам / Нет, лучше ты / Не знаю, что это значит
   - «Есть ли уже адрес сайта (домен)?» → Да, есть / Нет, нужно купить / Не знаю, что это
7. **Куда прислать план?** (ввод): Имя / Телефон или мессенджер / Email (опц.) + «Как удобнее связаться?» (один): Telegram / WhatsApp / Звонок / Email

**Три входа → три возврата** (по `briefEntry`):
| Вход | Приход | Возврат |
|---|---|---|
| `start-button` (кнопка на старте) | погружение | **моргание** → первый экран ВЕТКИ (пересадка на вторую ветку) |
| `corner-icon` (иконка в углу) | скоростной полёт сквозь сайт (0.6–0.8с, блюр, прерываемый тапом) | **моргание** → на экран ветки, откуда нажал |
| `walked` (дошёл по ветке) | последний рывок камеры | **обратное погружение** на шаг → к типам сайтов |

**Вызов возврата из брифа:** скролл за верхний край (порог 80–100px, когда бриф вверху) ИЛИ кнопка «назад» в шапке.

**Отправка:** формируется Word-документ (HTML→.doc через Blob, как в прототипе) + mailto с готовым письмом. TODO: заменить MY_EMAIL; для реальной отправки без почтового клиента — Formspree/Web3Forms.

**После отправки — экран подтверждения** (простое проявление, без полёта): «Бриф получен. Изучу и вернусь с планом работ в течение суток.» + кнопка скачать копию + мягкий выход. Очистить localStorage.

## 7. Типы сайтов (экран 3 ветки)

4 карточки. Интерактив: при наведении (ПК) / сразу (мобильные) — «посмотреть примеры» → переход в портфолио (моргание) с фильтром по типу.

- **Лендинг** — Подходит, когда нужно продать что-то одно: услугу, продукт, курс или акцию. Вся страница ведёт к одному — конверсии посетителя в звонок или заявку.
- **Сайт-визитка** — Подходит, когда за делом стоишь ты или небольшая команда. Рассказать, кто ты и что предлагаешь, показать работы и дать контакты. Обычно 4–8 страниц.
- **Корпоративный сайт** — Подходит, когда сайту нужно подробно отразить компанию: направления, команда, вакансии, документы, новости. Более 10 страниц.
- **Интернет-магазин** — Подходит, когда нужно продавать много и онлайн: каталог, корзина, оплата — покупка идёт без твоего участия.

## 8. FAQ и Портфолио (слои)

**FAQ** — вылетает из иконки, две колонки (мобильные — одна), фон блюрится + еле заметно темнеет, вопросы — аккордеон. 7 вопросов (тексты в konspekt_proekta.md, раздел 3.4): стоимость, сроки, что подготовить, обязательно ли всё сразу, смогу ли сам менять, кто делает, что если не понравится.

**Портфолио** — переход морганием, отдельный вид с фильтрами по типу сайта (и нише). Карточки: изображение + краткое описание + тип. Работы на старте:
- Лендинг арбитражного управляющего по банкротству физлиц
- Сайт-визитка швейного цеха: шторы и текстиль
- Сайт-визитка студии изделий из керамогранита: кухни, декор, мебель
- Корпоративный сайт завода нефтегазового оборудования

Без деления на «боевые/демо», без выдуманных метрик. Магазин пока не покрыт.

---

## 9. Фон-дым (отдельный слой, НЕ блокирует)

Реализуется отдельно (см. plan_fluid_smoke.md), навешивается на готовый каркас. На старте — заглушка: статичный перламутровый фон или лёгкая CSS-анимация градиента. Сайт должен быть полностью функционален БЕЗ дыма. Дым — улучшение, не фундамент.

---

## 10. Адаптив и доступность

- **Мобильные:** hover не работает — «посмотреть примеры» и подсказки показывать сразу/по тапу. Иконки по углам — в безопасных зонах (не под системными панелями). Полёты и погружения работают от тапа.
- **SEO-критично:** весь ключевой текст в HTML с самого начала (не появляется только по JS/действию). Раскрытие через CSS/JS — визуальное, контент доступен роботу и скринридеру сразу. Логотип — настоящий текст, эффекты через CSS.
- **`prefers-reduced-motion`:** отключает погружения/дым, заменяет на простые fade.
- Семантичный HTML, alt у изображений портфолио, клавиатурная навигация по брифу.

## 11. Порядок реализации

Строить каркасом, потом навешивать эффекты. После каждого этапа — рабочее состояние.

1. **Каркас + состояние.** HTML-структура всех экранов, объект state, роутер экранов (показ/скрытие), токены CSS. Переходы пока — мгновенные или простой fade
2. **Контент.** Все тексты по местам: старт, обещание, 6 фаз, типы сайтов, FAQ, бриф, подтверждение
3. **Бриф целиком.** Все 7 шагов, выбор вариантов, валидация обязательных, localStorage, формирование .doc + mailto, экран подтверждения. Это ядро конверсии — довести до конца
4. **Навигация и слои.** Три входа в бриф + три возврата (briefEntry!), иконки по углам, FAQ-слой, портфолио с фильтрами
5. **Фазы процесса.** Скролл с магнитом, уход карточки влево, подсказки
6. **Погружение.** Переходы камерой (scale+fade+blur), тайминги, моргание, скоростной полёт, обратное погружение
7. **Фон-заглушка → дым.** Сначала статичная заглушка, потом (отдельно) fluid solver
8. **Адаптив + a11y + reduced-motion.** Пройти по всем экранам на мобильном, проверить SEO-доступность текста
9. **Полировка таймингов.** Главное в ощущении «дорого/дёшево» — тайминги переходов. Крутить вживую

**Приоритет, если время ограничено:** этапы 1–3 (работающий сайт с брифом) — обязательный минимум, продаёт даже без анимаций. 4–9 — превращают в целевую версию.

## 12. Критерии готовности

- Посетитель проходит любой из путей и заполняет бриф
- Бриф отправляется, приходит .doc, работает скачивание копии
- Три входа/возврата работают корректно (не потерять, откуда вошёл)
- Прогресс брифа переживает уход-возврат в рамках сессии
- Весь текст доступен без выполнения JS (SEO)
- Работает на мобильном, уважает reduced-motion
- Тайминги переходов ощущаются дорого, не дёшево
